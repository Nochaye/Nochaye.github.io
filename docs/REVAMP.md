# StarCape 改版提示词与实施计划

## 提示词
翻修现有 StarCape 个人导航，保留既有有效入口，采用浅色纸张、森林绿和橙色点缀的中文工作台。提供分类、搜索、收藏；新增英语精读总览、真实数量、文章日期、按实际更新日的月历、独立 HTML 阅读器、查看计数，以及可以添加、删除、替换和编辑 HTML 元数据的本机后台。适配手机、键盘导航。数据不可虚构；来源不明的内容不得冒充浏览记录。

## 环境结论
- 原项目 Nochaye/Nochaye.github.io，纯静态 GitHub Pages，无构建系统、无后台、无 AGENTS.md，工作区初始干净。
- 当前云端 Linux 无 Windows Chrome/Edge 历史或书签。旧导航作为既有来源；News in Levels 和 Forge Blueprints 项目来自相关对话。支持导入浏览器导出的书签，不能声称统计过访问频率。
- 从每日 Level 1 对话中的生成代码恢复 2026-11-04 至 11-11 共八期。11-08 至 11-11 的实际生成日期是 11-11；其余为各期当日。不发布完整聊天记录或本机路径。

## 架构与步骤
1. 恢复八期离线 HTML，生成可验证的 JSON 索引。
2. 静态首页与精读阅读器，共享导航/文章数据；静态公开站浏览计数存于本浏览器，明确标记，收藏同理。
3. Python 标准库本机管理服务只监听 127.0.0.1，随机管理令牌、同源写请求校验，原子替换索引，删除移入忽略的备份目录。后台不依赖 GitHub 密钥。
4. 本机后台可读写真实仓库文件；GitHub Pages 无服务器，公开后台显示运行说明，不假装可以远程保存。
5. 构建 dist 作为 Pages 发布产物，排除管理服务、测试、备份。GitHub Actions 部署。
6. 功能、安全边界、数据与资源引用检查后提交并推送。当前 Sites 专用浏览器 QA 工具缺失，按技能限制不绕过其预览通路。

## 后续
跨设备总访问量和公网管理后台需要可部署的服务与认证配置；本次不把浏览器本地计数冒充全站统计。
